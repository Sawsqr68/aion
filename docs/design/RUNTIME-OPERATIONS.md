## 2. What the blind study proved about the runtime

Every one of five cold readers, across two independent panels, reconstructed the control-flow graph correctly and then stalled on the same missing layer: **engine semantics the file references but never defines.** The xhigh reader's calibration: control flow 8/10 legible cold, operational semantics 5/10 — "the prompts look procedural, but most of their contents are not engine-level steps." The specific gaps, all confirmed independently by ≥2 readers: what `node agent` binds to; what a retry IS (count basis, trigger conditions, session interaction, side-effect safety); what happens when retries exhaust; fork sibling-failure and empty-fork semantics; signal buffering/dedup/staleness; visit-cap counting and breach consequence; whether heartbeat-class failures can sink a run; where held escalations live. Each has a ruling below. The uncanny valley is not the syntax — it is the undefined runtime contract, and this doc's job is to define it.

## 3. Rulings — routing and service

**R1. Queue service becomes a durable, honest status; the indefinite wait dies.** The current dispatcher behavior (wait forever, `bridge.rs:453-505`) collapses "being served slowly" and "served by nobody" — the flagship's unserved-`general` incident class. Adopt the four-way taxonomy (blind-xhigh, unprompted; matches Temporal's `no_poller_tasks` weakness inverted): `NO_QUEUE_DECLARATION` (no deployment declares this queue — refusable at deploy/run-start per handshake), `NO_LIVE_POLLERS`, `POLLERS_INCOMPATIBLE` (capability/version/node mismatch), `SATURATED` (served, schedule-to-start latency growing). The run and the queue both surface the state with reason and last-compatible-poller age. Two distinct service policies per dispatch: **strict** (refuse at run start when the contract is known-absent — "don't start lying") and **durable_pending** (accept, mark `UNSERVED` immediately, alert out-of-band before expiry). Two distinct clocks: a service-availability deadline (nobody compatible) and a schedule-to-start timeout (compatible workers, growing queue); expiry produces a typed `WorkerUnavailable` failure, never a generic timeout. Mid-run worker vanishing parks visibly with alert — killing in-flight work over a blip is worse than the disease (agreed ruling, both bundles).

**R2. The task envelope and completion fencing.** Every dispatched task carries: task id, attempt number, execution generation, lease expiry, an opaque completion token, and an idempotency key (blind-xhigh specified this envelope unprompted; Temporal's RangeID fencing is the precedent for generation-gated writes). Completion is accepted only for the current lease and generation — a stale worker may submit; the server rejects. Scheduling atomically records the history event and the durable queue entry. Delivery is at-least-once and the doc says so plainly; exactly-once is a property of fenced idempotent effects, not of transport.

**R3. Sessions become first-class, and a retry is a NEW TURN.** `session_key` today is an application convention invisible to the engine (and reads as an ordinary parameter — blind-xhigh). Ruling: the engine recognizes a session as a runtime object — an affinity key that pins a logical session to a worker while the worker lives, so affinity is an optimization, never a single point of failure (Temporal sticky-execution's correct shape: losing stickiness loses performance, not correctness). Honesty about the fallback: today agent-session state lives on worker-local disk (e.g. norn's `~/.norn/session-store`), so rehydrate-elsewhere is NOT currently possible — until session state has a durable home, the stated fallback on worker loss is a FRESH session (continuity lost, correctness intact, and the run surface says so). Rehydrate-elsewhere becomes claimable only when a durable session store exists; this doc does not claim it before the substrate does. The undefined triple from both panels — retried agent action: same turn, new turn, or replay? — is ruled: **a retry is a new turn in the same session, carrying the attempt number**, and the worker contract states what the implementation is told about the failed attempt. Side effects behind a retry are fenced by the idempotency key (action site span + run + stable fence across attempts), making non-idempotent effects (merge, push, message) exactly-once-or-refused.

**R4. Retry taxonomy, counted and triggered precisely.** `retry N` means N further attempts after the first (N+1 total) — both Sol readers hit the off-by-one cold; the language reference states it in one line (Bundle A owns the wording). Retry triggers follow the never-die durability doctrine: transient failures (worker loss, timeouts, connection) retry per policy; non-transient failures (contract-shape rejection per the handshake, typed action refusal) fail the attempt loudly without burning retries on an outcome that cannot change. Schema rejection is engine-side and non-retryable. Action retries do not count as step visits; the visit cap counts step entries including the first (Bundle A's `max N visits else` repair states the breach edge).

**R5. The advisory action class.** Side-channel actions (heartbeats, notifications) declare `advisory`: retry exhaustion emits a visible warning event on the run and surfaces in the console; it never faults the step. Both panels independently found the current posture undefined and identified that a meridian outage could sink an otherwise-healthy run. Non-advisory actions require an `on failure` edge wherever a declared retry can exhaust (Bundle A §2.3, scoped to non-advisory at this doc's request).

## 4. Rulings — worker lifecycle

**R6. The server deploys workers; the hybrid is the model.** Managed local workers become the default capability, external workers a first-class escape hatch — never the reverse. A durable `WorkerDeployment` record carries: content-addressed artifact hash, namespace, queue(s), capabilities/activity types, replica count, placement, resource limits, version policy. A per-node in-process reconciler (the Kubernetes lesson kept: desired-state record + idempotent reconciliation; everything else rejected) materializes supervised processes from the exact hash: local restart first (OTP supervision discipline, bounded intensity), cross-node replacement second when placement is durable (§6). Drain-then-replace upgrades adopt Temporal Worker Deployments' semantics — Current/Ramping versions, Pinned/Auto-Upgrade runs, drainage tied to durable in-flight work — but joined to actual process ownership, which Temporal explicitly refuses ("routes tasks, tells you to run the workers yourself"). External workers register the same identity and contracts but are labeled `ownership=external`: observed, routed to, never restart-guaranteed, and the console never conflates **managed-and-guaranteed**, **external-and-connected**, and **unserved**. Registration passes the handshake gate (hash-pinned contract refusal) for both tiers. Batteries included: a stock server serves `shell` and `agent` defaults the moment it starts — the empty-fleet cliff is the number-one operator confusion (both panels, unprompted, matching the out-of-box doctrine).

**R7. Idle liveness.** Worker leases cover the connection, not just in-flight tasks — closing the scout's idle-wedge blind spot (`heartbeat.rs:19-43`): an idle worker heartbeats its lease; expiry marks it dead, removes it from service counts, and (if managed) triggers supervised restart.

## 5. Rulings — kill guarantees

**R8. Killed means stopped, verified, and fenced.** Containment is created BEFORE user code runs, owned by the worker harness so authors cannot forget: Linux — one cgroup v2 per managed worker instance, graceful stop then `cgroup.kill` (documented to handle concurrent forks/migrations; strictly stronger than `kill(-pgid)`), `PR_SET_PDEATHSIG` as defense-in-depth only (cleared across fork/exec transitions, misses an already-dead parent); macOS — fresh process group + a start-barrier launcher holding a private dead-man FD whose writer lives only in the server (server death → EOF → launcher kills the group), kqueue `EVFILT_PROC/NOTE_EXIT` for observation, with the honest caveat that a hostile daemonizing child needs a sandbox boundary, not supervision; Windows (recorded for completeness) — Job Objects with kill-on-close, breakaway disabled. `Killed` is emitted only after OS-level confirmation that containment is empty — never after merely sending the signal. Every incarnation carries a kill-generation token; late completions from a dead incarnation are rejected (R2 fencing). A standing orphan-scan regression test: spawn a grandchild, kill through every path (cancel, worker stop, server shutdown), assert the whole tree is gone. Current known orphan surfaces to fix: `worker_shell.rs:142-163` (direct child only, no group) and example harnesses using blocking `Command::output()` with no cancellation hook (`examples/agent-dev/worker/src/shell.rs:107-145`).

**R9. Cancel cascades; stop becomes targeted; drain covers everyone.** The parent-close build (checklist already enumerated at `docs/design/parent-close/checklist.json`) becomes a committed phase: cancel propagates recursively to spawned and implicit children, durable across recovery — the "parent cancelled, six fan children kept Running" gap dies. `worker stop <id>` and `worker drain <id>` become real administrative operations (today only global shutdown exists). The shutdown drain broadcast reaches liminal-attached workers too (`registry.rs:775-779` currently skips them — a straight defect).

**R10. Killed-but-resumable is a distinct, deliberate state.** Resumable means: durable history intact at the frontier, effects fenced, resume explicit and audited — never silent reanimation, never "whatever memory was present when killed." Event-history replay is the authoritative resume substrate; snapshots accelerate it; CRIU-style process checkpointing is rejected as authority (Linux-only, kernel/capability-bound, restore-not-guaranteed per its own manual). The norn driven-mode dead-man switch is this machinery applied: driver death kills the child's containment (R8), the child's session survives durably, and resumption re-enters at the frontier.

## 6. Rulings — the server network

**R11. Membership triggers; epochs authorize.** The composite the landscape survey converged on: Restate-shaped internals (desired assignment + local reconcilers + durable leader epochs + log replay), Temporal-correct ownership movement (fence + reload from durable state, never live state transfer), OTP-grade liveness sensing that is NEVER promoted to write authority (`global`/`pg` documented-unsafe under partitions; gossip is a sensor). Aion already has the fenced-adoption seam (`engine/api.rs:302-419`); the build is durable membership — replacing the boot-static denominator (`store.rs:92-133`, the #146 area) with quorum-committed membership records in haematite, where a membership event triggers reconciliation and a quorum epoch gates every write. Cross-server pickup = observe assignment change → quorum read-modify-write of ownership epoch → old epoch loses write permission → replay durable log → advertise ready.

**R12. Sequencing stays single-node-first.** Single-node durability (survive process restart) is complete before multi-node placement of *workers*; the durable-membership build is additive on the existing fenced-adoption machinery, not a rewrite. `WorkerDeployment` records replicate through haematite exactly like placement, so whole-server death moves desired worker replicas to survivors with the same fencing. Contract records (including Bundle A §3.1 signal contracts) replicate the same way — cross-server signal send is boundary-checked for free. Parked-on-signal runs survive server death because waiting lives in the log. The `#[ignore]`d OS-process kill-9 gates (`lsub5b`, `parked_timer`) run as a named phase gate for this section, not as an afterthought.

## 7. Rulings — engine-owned state the prompts currently carry

**R13. Escalation state is engine state.** The held-escalation set becomes durable run state — declared, queryable, console-surfaced. Partial ruling batches leave a visible held-set; agent diligence stops being load-bearing (all five readers found the silent-drop hazard).

**R14. Signal carriage semantics are stated and durable.** Per declared signal: buffered FIFO from run start (a signal sent before the wait is delivered at the wait), duplicates queue (dedup is the workflow's typed concern unless a dedup key is declared), buffered signals are durable state that survives failover and replay — the scout confirms signal delivery rides run history, and the conformance fixture Bundle A §3.1 calls for pins it. Send-side: contract-record lookup by workflow content hash, typed refusal at the sender, never a re-parse of stored source.

## 8. Build sequencing (ratifies WORKER-LIFECYCLE-BUILD.md W-0..W-6, amended)

Phase 1 — service honesty and kill floors (smallest, highest incident-class value): R1 unserved status + policies at the bridge seam; R5 advisory class; R7 idle leases; R9 targeted stop/drain incl. liminal; R8 containment in `worker shell` + worker harness with the orphan-scan test. Seam ordering: R1's four-way taxonomy needs the handshake contract records to tell `NO_QUEUE_DECLARATION` and `POLLERS_INCOMPATIBLE` apart from `NO_LIVE_POLLERS` — Bundle A's Phase-1 handshake build lands first at the bridge seam and R1 builds against its records. Handshake §2.3 (as amended) and R1 state the same policy: structural unservability refuses unconditionally; `NO_LIVE_POLLERS` admits declared `durable_pending`; strict is the default. Phase 2 — lifecycle: R6 WorkerDeployment records, reconciler, managed defaults, console controls (W-1..W-6 as staged, artifact kind added to the package manifest per W-1). Phase 3 — semantics: R2 envelope + fencing, R3 sessions + retry-as-new-turn, R4 taxonomy, R13 escalation state, R14 signal carriage. Phase 4 — network: R11 durable membership, R12 cross-server worker placement, kill-9 gates as the exit criterion. Each phase lands operator-visible surface, honoring the working-demo doctrine. Amendments to W-0..W-6: registration/contract gating defers to the handshake doc rather than W-3's sketch; worker versioning adopts R6's Temporal-derived semantics rather than W-5's single-version assumption.

## 9. Non-goals

No OS init supervision (launchd/systemd) as the worker supervisor. No external orchestrator, scheduler, or database in the required path. No replay-determinism imposed on worker/business logic — determinism stays in the engine control plane; tasks are ordinary idempotent fenced calls (Temporal's sharpest adoption edge, deliberately avoided). No gossip-as-authority. No host-addressed routing. No CRIU-class process checkpointing as durable truth. Sticky/session affinity never becomes load-bearing for correctness.
