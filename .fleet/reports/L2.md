## Transcript window

The default request is **50 retained transcript events** (`DEFAULT_LIVE_STEP_TAIL`). This is large enough to show useful immediate context without silently imposing an unbounded or unusually expensive read on every two-second refresh. The operator can adjust it through the visible **Transcript tail** selector to **20, 50, or 100 events**; changing it changes the query key and issues a read for the selected bound.

## Poll cadence and stop condition

The cadence is **2,000 ms**. A two-second interval keeps volatile ownership, heartbeat-note, and retained-tail information useful without copying the one-second child-start cadence into a read that may include transcript data. A push path is available on this page: `useLiveWorkflowEvents` receives workflow history events over the socket and remains the authority for terminal state. It does **not** carry `describe-live` ownership, live-registry heartbeat notes, or transcript-keyspace state, so this surface still requires polling. `live.isTerminal` disables both the query and interval. The test named **`terminal query options stop the declared 2s cadence before another read`** declares the 2,000 ms window, advances a fake clock through three windows, and asserts the reader remains at one call after terminal.

## Operator wording

`NoLiveOwner`, healthy hand-off wording:

> “No live owner — this may be the ordinary hand-off between dispatch and lease.”

`NoLiveOwner` with a non-empty unserved verdict:

> “No live owner — the fleet reports this dispatched activity cannot currently be served.”

Connected live owner with empty capabilities:

> “Live owner connected — observability-only; this harness advertises no intervention controls.”

Visible refusal when there is no owner:

> “Intervention controls unavailable: no live owner is connected.”

Visible refusal for unadvertised primitives:

> “Other intervention controls are withheld because this harness does not advertise those primitives.”
