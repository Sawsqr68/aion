## The settled design you test against (K8 ruling, Waffles 2026-08-14,
## extending the K6 precedent under Tom's 2026-08-12 delegation)

Actions travel as a new facet on the component declaration — a RECORD ENTRY
on the registry feed, never code. The facet:

- Name `manifold.facet.actions@v1`. Body
  `{ "actions": { "<kind-token>": [ <action>... ] } }`.
- An action is one of exactly TWO closed v1 primitives:
  - `{ "primitive": "respond", "label": "<literal>", "kind":
    "<record-kind-token>", "body": { ...literal template... } }` — exactly
    these four members; `label`/`kind` non-empty strings; `body` an object;
    a template member named `shape` or `re` is MALFORMED (it would collide
    with the sent envelope) and refuses by name.
  - `{ "primitive": "choose", "from": "<list-field>", "kind":
    "<record-kind-token>" }` — exactly these three members; `from`/`kind`
    non-empty strings.
- deny-unknown-fields at EVERY level. An unknown primitive name, unexpected
  member, missing member, non-object facet body, non-object `actions`,
  non-array roster, or non-object action is MALFORMED and refuses BY NAME —
  the refusal names what was found and what is permitted, and says the v1
  vocabulary is `"respond"` and `"choose"` and grows only with a page
  release. A malformed roster refuses that token's actions WHOLE and is
  DISCLOSED. Wording register precedent:
  `surface/page/src/declared-face.ts:62-84` (element refusals) and
  `:215-235` (disclosure sentences).
- A `choose` whose `from` field on the acted-on payload is not an array is a
  RENDER-time refusal of THAT ACTION ONLY — words naming the field, saying
  it is not a list — and sibling actions still render (the exact posture of
  `declared-face.ts:171-179`).
- Pressing a control IS the act (Tom's click-is-the-act ruling): one body
  string goes through the room's existing write path, no composer detour.
  Sent bodies (precedent `surface/page/src/poll.ts:252-259`):
  - respond: `{ "shape": <action.kind>, ...<action.body members>,
    "re": <entry.record> }`
  - choose, item at index i: `{ "shape": <action.kind>,
    "re": <entry.record>, "option": i, "choice": <the item, verbatim> }`
  Member SET and VALUES are the contract, serialization order is NOT — your
  cases PARSE the captured body string; never byte-compare it.
  `entry.record` is the durable entry reference
  (`surface/page/src/kind-render.ts:50-63`); a null one refuses the press.
- No write path ⇒ controls render `disabled` with the refusal in words
  (register of `surface/page/src/composition/conversation/mount.ts:322-327`:
