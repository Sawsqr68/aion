## Judgment calls inside the ruled floors

- **Refusal wording:** wording follows the existing plain-sentence register and names the malformed action/member/field. Unknown primitives explicitly state that the v1 vocabulary is `"respond"` and `"choose"` and grows only with a page release. A refused write-path placement is shown verbatim where the button was pressed. A null durable record produces: “This entry holds no durable record name, so the action cannot name what it answers. Nothing was sent.”
- **No write path:** controls that can otherwise render are disabled, and the bar adds one `declared-action-refusal` containing both required substrings, `no write path` and `Nothing was sent.` No press is accepted without a door.
- **Choose over a non-list:** only that choose action becomes a `declared-action-refusal`; sibling actions continue rendering.
- **No-face edge:** actions are not independently injected into the feed. If no resolvable declared face exists, v1 renders no action bar, exactly as ruled.
- **Pending state:** a placed press marks only the pressed button with `data-pending="true"` and disables every button in that bar. No persistent pending ledger was introduced; the next existing redraw builds a fresh bar.
- **Durable-name timing:** buttons remain honest controls until pressed; if `KindEntry.record` is null, the press renders the durable-name refusal and does not call the write path.
- **Choice labels:** string choices are used directly; other literal JSON values use the same readable JSON/string conversion posture as `declared-face.ts`. The body always carries the original choice value verbatim.
- **Optional write-path narrowing:** the mount uses a non-null assertion only inside the branch that has already established `options.place !== undefined`; this preserves the planner-pinned direct forwarding while satisfying TypeScript's property-narrowing rules across the callback.
