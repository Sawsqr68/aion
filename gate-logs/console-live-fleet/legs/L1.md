## 5. THE SEAM — reproduce this text exactly

Your client's method must be assignable to this. Identical parameter order, identical
nullability, identical return. L2 has the same text.

```ts
import type { DescribeLiveResponse, Namespace, RunId, WorkflowId } from '@/types';

/** How much transcript tail to request. Omitted = the server reads none. */
export type LiveStepTail = number | undefined;

/** The one call the live-step surface needs. L1 implements it; L2 consumes it. */
export type LiveStepReader = {
  describeLive(
    namespace: Namespace,
    workflowId: WorkflowId,
    runId: RunId | null,
    tail: LiveStepTail,
    signal?: AbortSignal
  ): Promise<DescribeLiveResponse>;
};
```

You do **not** create `live-step-port.ts` — that file is L2's. You simply make
`DescribeLiveReadClient.describeLive` match this signature.

### R-L1-3 — `tail` HAS NO DEFAULT, and you must not give it one

This is the requirement most likely to be got wrong, so it is stated at length. The server's own
doc comment (`describe_live.rs:57-64`):

> Omitted returns `TranscriptTail::NotRequested` — no tail is read and nothing is claimed about
> the stream. **There is deliberately no default window**: how much transcript a caller wants is
> the caller's decision, and a number invented here would be a cost every caller paid without
> asking.

So: `tail === undefined` → the `tail` key is **absent from the JSON body**, not `null`, not `0`,
not a number you picked. Choosing the window is **L2's** job, and L2 states its number and reason
in its own report. If you default it, you have taken a decision that is not yours and made every
caller pay for it.

Cover this with an explicit test asserting the serialized body has no `tail` key when the caller
omits it (§7).

### R-L1-4 — validate the response; never silently coerce

Follow `children-read.ts:70-107` (`readChildLeg` and friends): every unexpected shape throws a
typed `ApiError`, never a `null`-coalesce that invents an answer. Specifically:

- non-object body → `ApiError`
- `current_step` present but not an object → `ApiError`
- `open_steps` / `transcript_streams` / `unserved` present but not arrays → `ApiError`
- the tagged unions (`state`, `liveness`, `note`, `transcript`) carrying an unknown tag → `ApiError` naming the tag it got

The `NoLiveOwner` liveness variant and the `NotRequested` transcript variant are **valid,
expected answers** — they are the honest "nothing to report", and treating either as an error is
a reject. Read `crates/aion-core/src/describe_live.rs:11-27` for why every absence in this shape
is typed; that doc block is the design rule you are preserving across the wire.

Absences that are legitimately `null` per the type (`summary`, `current_step`,
`CurrentStep.attempt`, `TranscriptStreamHead.activity_type`, `OpenStep.node`) pass through as
`null`. Do not conflate a legitimate `null` with a malformed field.

### R-L1-5 — abort support

Accept and forward an optional `AbortSignal`, as `children-read.ts:56` does
(`...(signal === undefined ? {} : { signal })`). L2 polls, and its react-query integration will
cancel in-flight reads; without this, a navigating operator leaks requests.

## 7. TESTS — floors, not ceilings

`src/lib/api/describe-live-read.test.ts`, driven by an injected `fetchImpl` double, the way
`children-read.test.ts` and `transcript-read.test.ts` do. At minimum:

1. Request body is exactly `{namespace, workflow_id, run_id}` with **no `tail` key** when tail is omitted (R-L1-3).
2. Request body carries `tail: <n>` when the caller supplies one.
3. `run_id: null` is sent when the caller passes null.
4. A full happy-path response parses: `current_step` with a `Dispatched` state, a `LiveAttempt`, `AttemptLiveness::Live` with a non-empty `capabilities.supported`, a `HeartbeatNote::Reported`, a `TranscriptTail::Window`.
5. `AttemptLiveness::NoLiveOwner` parses cleanly and is **not** an error.
6. `TranscriptTail::NotRequested` parses cleanly and is **not** an error.
7. `HeartbeatNote::Unavailable` with `restarted_since_attempt_began: true` parses cleanly.
8. `current_step: null` (run not inside an activity) parses cleanly.
9. Non-2xx → `ApiError` carrying the status.
10. Malformed body (non-object; `open_steps` not an array; unknown `liveness` tag) → `ApiError`, one test each.
11. An `AbortSignal` is forwarded to `fetchImpl`.

Fixtures must be built from the shapes in `crates/aion-core/src/describe_live.rs`. Where you want
a real server-shaped example, `crates/aion-server/src/api/http/describe_live_tests.rs` is the
source of truth for what the handler actually emits — prefer copying from there over inventing.

Beware a fixture where the right answer and a plausible wrong answer coincide: a `NoLiveOwner`
test whose expected rendering is also what an empty-capabilities `Live` would produce
distinguishes nothing. Make the two visibly different in your assertions.
